# 范围与实施方案

最初设计日期：2026-10-23。当前阶段：Alpha。核心流程已实现，具体覆盖范围和剩余验证见 [validation.md](validation.md)。

## 已接受的目标

为 Windows 官方稳定版 Codex 提供手动运行的更新诊断与修复工具。首个实测平台为 x64，提供 macOS 精致应用的视觉质感，发布便携包和安装版，普通用户不需要开发环境。技术栈为 Tauri 2、Rust、React/TypeScript、Tailwind CSS、定制 shadcn/ui。

核心闭环：只读诊断 → 展示修复动作与保存提示 → 校验包 → 退出目标客户端 → 独立部署 → 验证注册版本和运行版本 → 报告更新提示状态。Codex++ 不作为核心功能运行前提；不卸载、不重置、不修改认证或模型配置。

## 建议的实现结构

- React 界面：诊断、修复预览、执行进度、分项结果、可展开诊断详情和设置。
- Rust 核心：平台发现、版本模型、来源与包验证、修复状态机、每用户并发锁、结构化事件和本地状态。
- Windows 适配：包注册、暂存发现、签名验证、部署、精确进程识别、原生启动和提示检查。
- 独立执行器：UI 退出后继续受控执行已开始的部署；持久记录运行标识、步骤、结果与执行器状态，重开 UI 可接入同一任务。
- 受限桥接：前端调用固定业务命令，部署执行器校验参数与任务归属；不向界面暴露任意 shell 执行能力。
- Windows API 或固定脚本的具体选择属于实施细节，以兼容性和可验证性为依据；不保留个人用户名、固定增强端口或第三方私有启动参数。

## 结果与异常模型

包部署、目标版本运行、界面提示分别报告。区分无更新、可修复、缺少包、渠道不同步、网络失败、校验失败、等待退出、权限取消、部署失败、启动失败、提示仍存在和提示未验证。

版本型号明确分为 MSIX 包版本、应用显示版本与应用构建编号，不以 Electron 可执行文件的运行时版本判断 Codex 是否已更新。源查询失败时显示无法判断，不显示“已经最新”。

无可靠来源、包身份不符、签名失败、发现不支持的安装类型或用户上下文变化时停止相应动作，并说明原因。不通过猜测下载地址弥补版本源缺口。

## 执行与数据约束

- 关闭客户端先请求正常退出；超时后等待用户处理或重试，强制结束仅作为用户明确选择的操作。
- 下载阶段允许取消。Windows 部署开始后不直接杀部署进程；关闭界面后独立执行器继续记录结果，再次打开可接入。关机、注销等外部中断后重新诊断实际状态，不把旧状态文件当作成功证据。
- 首版诊断仅保存在本机，不收集后台遥测。用户主动导出时提供脱敏预览，只导出固定字段，不包含认证、聊天内容、模型配置或原始全量系统日志。
- 项目名称 Codex Updater，MIT 开源，明确非官方工具。维护者为 Kabi (paiwoo)。
- 首版中英文；验收覆盖浅深主题、键盘、高 DPI、真实版本核对和本机占用阻止注册场景。预览版清晰区分模拟测试与实机测试，未测平台不标记已支持。

## 实施顺序

1. 整理现有脚本为历史实现参考，明确新旧入口；创建项目结构、依赖锁和构建说明。
2. 实现只读诊断和版本模型，接入真实系统与发布源，形成可解释报告。
3. 构建采用真实状态模型的 UI，设计演示数据有明确标记。
4. 实现可独立执行的修复状态机、包验证、进程退出、部署与启动。
5. 加入诊断导出、国际化、主题、异常恢复与单实例接入。
6. 验证后构建便携包和安装版，准备源码、许可、文档、发布校验和与 CI。

## 验证计划

- 核心逻辑：数字版本比较、来源分歧、非预期响应、签名与包身份失败、状态转换、并发及恢复。
- Windows 集成：已暂存与下载两条路径，用户取消权限、应用未退出、部署成功但启动失败、提示无法验证。
- UI：完整状态展示、键盘焦点、窗口缩放、高 DPI、语言切换、减少动画、纯色材质回退。
- 发布：干净构建、产物可启动、便携包与安装版运行时策略，真实记录包大小、冷启动、空闲内存和峰值内存。
- 实机更新：本机已识别问题作为候选用例；实际退出 Codex 前应有可复查的构建与动作说明，不能在当前访谈中自行关闭正在使用的客户端。

## 公开发布范围

源码、维护文档、示例数据截图和校验过的工具发布包可以公开。个人日志、运行目录、认证、原始工作草稿与 Codex 官方安装包不进入 Git 或发布附件。Alpha、Beta 和 RC 使用语义化预发布版本，并在 GitHub Releases 明确标记；安装与恢复验收完成前不宣称稳定版。
