## 真实只读诊断

环境：Windows 10 Pro 22H2 x64，已安装系统 WebView2。

最终便携包读取的注册版本与本次官方源版本均为 `26.1021.3705.0`。这表示包版本达到本次渠道提供值；更新提示单独记录为 `not_detected`，不据此断言用户看到的提示已经消失。

历史诊断曾发现旧包注册被运行中应用阻止，以及发布源暂时连接失败。历史占用记录现在明确标为“过去 24 小时内”，网络错误区分超时、连接失败和 HTTP 状态。原先下载误用清单的 30 秒超时已修正：清单请求限时 30 秒，包下载总时限 30 分钟；分块传递使等待网络数据时仍可检查取消。

本机另有此前由外部操作产生的已完成更新记录；本轮检查没有触发这些更新，不能把该记录当作本轮恢复功能的真实部署验收。

## 软件内的恢复操作

| 状态                     | 后续操作                                                       |
| ------------------------ | -------------------------------------------------------------- |
| 下载失败                 | 重新下载并继续；不部署未完成的文件                             |
| 包校验失败               | 重新下载并校验，继续保留所有签名与身份检查                     |
| 应用占用                 | 重新等待或另行确认强制结束；已失败时可重新退出并继续           |
| 部署失败、取消或执行中断 | 核对实际注册版本，再执行仍需要的步骤；不会与尚在进行的部署并行 |
| 已部署但启动未验证       | 继续启动和验证，不重复安装已注册的目标包；旧版进程先正常退出   |
| 权限失败                 | 软件内重试部署；持续的 Windows 权限或企业策略限制仍会阻断      |

继续修复需要保存工作确认，保留旧记录并建立新任务。官方目标发生变化时，在软件内重新检查并审阅新方案。没有可靠包、身份或签名不通过时停止，不通过卸载、重置、猜测 URL 或静默提权强行继续。

## 内存观测

用同一脚本、同一路径比较旧包与最终包：不打开调试接口，启动 45 秒后读取进程树，再最小化 30 秒。每次均为应用与 WebView2 共 7 个进程。两次窗口都未稳定取得前台焦点，因此只比较最小化结果。

| 最小化 30 秒 |    修改前 |    最终包 |         单次变化 |
| ------------ | --------: | --------: | ---------------: |
| 私有内存合计 | 255.3 MiB | 281.9 MiB | 单次波动，未下降 |
| 工作集合计   | 427.8 MiB | 150.0 MiB |       减少 64.9% |

已加入 WebView2 后台低内存提示、窗口失焦时的 `TrySuspend`、重新获得焦点时的 `Resume`、启动时的焦点判断、隐藏窗口时暂停前端轮询，以及无任务时停止轮询；移除了弹窗背景模糊。此次工作集合测量明显下降，但私有内存没有同步下降，不能把它解释成所有内存指标都降低。暂停由运行时尽力执行，旧版 WebView2 可能只应用低内存目标级别。工作集合计包含共享页，不能等同于物理内存净占用。

原始记录保存在被忽略的 `.local/native/`；使用 `scripts/measure-memory.ps1` 可复测。未测部署期间峰值，未形成多机性能保证；私有内存仍为数百 MiB。

- EXE 和安装程序未代码签名，Windows 可能显示未知发布者或 SmartScreen 提示；官方 Codex 包的签名仍会校验。
